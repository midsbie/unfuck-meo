#+title: unfuck-meo

Workarounds for MEO's customer-hostile equipment, one command per problem:

- ~meo-ipv6-fix~ :: IPv6 sharing rules reverting to IPv4 on the MediaAccess TG789vac v2 router.

* Installation

From this checkout, with [[https://docs.astral.sh/uv/][uv]]:

#+begin_src sh
uv tool install .
#+end_src

Python 3.11+; standard library only.

* meo-ipv6-fix

Restores IPv6 *Game & Application Sharing* rules on a MEO (Technicolor) MediaAccess TG789vac v2.

** Problem

IPv6 rules revert to IPv4 over time, breaking inbound access to the device.  The sharing page hints at why:

#+begin_quote
If the device has no IPv6 it will assign the corresponding IPv4 for the game or application
#+end_quote

Probable mechanism: on some event (reboot, device entry expiry, ...) the firmware re-evaluates rules, downgrades those whose device has no known IPv6 address, and never upgrades them back.

** Usage

~meo-ipv6-fix DEVICE...~ logs in to the web UI and applies the manual fix to each IPv4 rule of each ~DEVICE~: /Edit/, /IP Version/ to IPv6, /Apply/.  The router recreates the rule as IPv6 under a new id.

~DEVICE~ is one of:

- Name :: as the router lists it, e.g. =nas=.
- MAC address :: colon-separated, any case, e.g. =02:00:00:00:00:01=; survives the router renaming the device.  Hyphenated MAC addresses are valid hostnames, so taken as names.

Behaviour:

- Preconditions :: the router lists a global IPv6 address for the device, else it recreates the rule as IPv4; the edit form targets that rule with the device selected.
- Verification :: every change is re-checked.
- Output :: one line per changed rule, per failed canary (router checked, or check deferred) and per canary recovery; none otherwise.
- Errors :: stderr, exit status 1.  A failed logout is a warning only: the rules are already fixed.

#+begin_example
$ meo-ipv6-fix --dry-run nas
nas: Deluge (UDP 59601 - 59601): IPv4 -> IPv6 (dry run)
$ meo-ipv6-fix nas
nas: Deluge (UDP 59601 - 59601): IPv4 -> IPv6
$ meo-ipv6-fix nas
$
#+end_example

Router access; options override the environment:

| Setting  | Default                | Environment    | Option     |
|----------+------------------------+----------------+------------|
| URL      | =http://192.168.1.254= | ~MEO_URL~      | ~--url~    |
| User     | =meo=                  | ~MEO_USER~     | ~--user~   |
| Password | =meo=                  | ~MEO_PASSWORD~ |            |
| Canary   | none                   | ~MEO_CANARY~   | ~--canary~ |

*** Canary

Logging in every few minutes loads the router's web server, seen to stop answering after hours of it.  A canary, a URL reachable from the Internet only through the rules, limits logins to when a rule has reverted: 2xx leaves the router alone; anything else (error status, timeout, DNS failure) prints why and proceeds.  Every router login is thus preceded by a =canary failed= line.

#+begin_example
$ meo-ipv6-fix --canary https://cloud.example.com/ nas
$ meo-ipv6-fix --canary https://cloud.example.com/ nas
canary failed: <urlopen error timed out>; checking the router
nas: HTTPS Server (TCP 443 - 443): IPv4 -> IPv6
#+end_example

A proxied DNS entry whose only origin record is the device's IPv6 address works from inside the LAN: the request goes out to the provider and back in through the WAN side.  The URL must be served by the origin, not a cache, or the canary answers while the device is unreachable.  Requests carry User-Agent =unfuck-meo=, for bot protection to allow.

The canary also fails when the device, provider or uplink is down, which no router check fixes.  With ~STATE_DIRECTORY~ set, as the units' ~StateDirectory=~ does, logins are at least 15 min apart: =$STATE_DIRECTORY/last-login= records the last; a deferred run prints when the next is due and exits 0; the file goes once the canary answers again.  An unusable directory is an error that leaves the router alone, since an unrecorded login would lift the spacing.  Without ~STATE_DIRECTORY~, as in manual runs, every failure checks the router.

#+begin_example
$ export STATE_DIRECTORY=$(mktemp -d)
$ meo-ipv6-fix --canary https://cloud.example.com/ nas
canary failed: HTTP Error 522: Origin Connection Time-out; checking the router
$ meo-ipv6-fix --canary https://cloud.example.com/ nas
canary failed: HTTP Error 522: Origin Connection Time-out; router check deferred until 14:35
$ meo-ipv6-fix --canary https://cloud.example.com/ nas
canary answers again
#+end_example

** Periodic execution with systemd

Scope follows the effective user; ~prefix=...~ overrides the scope's default prefix.  User paths follow ~XDG_CONFIG_HOME~ and ~XDG_STATE_HOME~ when set.

|               | User scope                     | System scope                     |
|---------------+--------------------------------+----------------------------------|
| Invocation    | ~make install~                 | ~sudo make install~              |
| Command       | =~/.local/bin/meo-ipv6-fix=    | =/usr/local/bin/meo-ipv6-fix=    |
| Units         | =~/.config/systemd/user/=      | =/usr/local/lib/systemd/system/= |
| Configuration | =~/.config/meo-ipv6-fix.env=   | =/etc/default/meo-ipv6-fix=      |
| State         | =~/.local/state/meo-ipv6-fix/= | =/var/lib/meo-ipv6-fix/=         |
| Manager       | ~systemctl --user~             | ~systemctl~                      |

User scope:

#+begin_src sh
make install
$EDITOR ~/.config/meo-ipv6-fix.env  # set MEO_DEVICES; credentials optional
loginctl enable-linger
make enable
#+end_src

Lingering is required: without it the user's systemd manager, hence the timer, runs only while the user is logged in.

System scope, for an always-on host:

#+begin_src sh
sudo make install
sudoedit /etc/default/meo-ipv6-fix
sudo make enable
#+end_src

- ~make install~ :: copies files only: no systemd contact, timer inactive, existing configuration preserved.
- Configuration :: ~MEO_DEVICES~ lists the devices by name or MAC address; empty in new files, so set before ~make enable~.  ~MEO_URL~, ~MEO_USER~, ~MEO_PASSWORD~ and ~MEO_CANARY~ are optional.
- ~make enable~ :: reloads the scope's systemd manager and enables the timer: first run 2 min after boot, then every 5 min.

Changes and problems go to the journal.  User scope: add ~--user~.

#+begin_src sh
journalctl -u meo-ipv6-fix
systemctl list-timers meo-ipv6-fix.timer
#+end_src

Removal preserves configuration.  User scope: drop ~sudo~, use ~systemctl --user daemon-reload~.

#+begin_src sh
sudo make disable
sudo make uninstall
sudo systemctl daemon-reload
#+end_src

Use one scope throughout.

** Router protocol

Web UI behaviour relied on:

- Login :: ~POST /login.lp~ with ~user~, the form's ~rn~, and ~hidepw~: an HTTP-digest-like hash of the password from the ~realm~ and ~nonce~ in the login page.
- Rules :: form ~ServiceCfg~ on ~/cgi/b/games/cfg/?be=0&l0=3&l1=4~.  Buttons post the form back to the same URL: field ~0~ is the action, ~1~ the key, ~2~ the page's one-time token.
  - /Edit/: action 21, key = rule id.
  - /Apply/ (edit form): action 10; field ~39~ = IP version (~4~ IPv4, ~41~ IPv6).
- Device page :: linked from the rules table; shows the device's IPv6 address.

** Backlog

- Rule selection :: fix only some of a device's rules (e.g. /HTTPS Server/ but not /Deluge/); today all are fixed.  Per-device rule lists outgrow ~MEO_DEVICES~ and call for a configuration file.
- Verbose mode :: ~-v~ for manual runs, one summary per device (e.g. =nas: 3 rules, all IPv6=); systemd runs stay silent.
- Devices without rules :: an error today, which catches misspelt devices; could be a warning.
- HTTP timeout :: fixed at 15 s; could be an option.
